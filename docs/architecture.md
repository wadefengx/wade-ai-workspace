# 架构（Phase 0）

## 边界

- **前端**：负责页面呈现、会话状态与 API 调用；不直接访问数据库或容器运行时。
- **后端 API**：负责认证、工作区元数据、参数校验与授权；是客户端访问数据的唯一入口。
- **工作区运行服务**：负责创建、启动、停止和清理隔离的开发容器；不承载业务数据查询。
- **数据库**：保存用户、工作区及其生命周期元数据；不保存容器内的临时文件。

Phase 0 先建立可独立演进的边界，不引入任务队列、实时协作或多集群调度。

## Docker 拓扑

```text
Browser
   │ HTTPS
   ▼
Frontend ──HTTP──► API ──► PostgreSQL
                     │
                     ▼
              Docker Engine
                     │
                     ▼
          workspace-<id> containers
```

- 前端、API、PostgreSQL 由 Compose 编排，位于同一内部网络。
- API 是唯一可访问 Docker socket 的服务；前端和数据库均不挂载该 socket。
- 每个工作区使用独立容器、卷和受限网络；容器名称及标签携带工作区 ID，便于回收。
- PostgreSQL 仅暴露给内部网络；对外入口仅为前端/API 的反向代理端口。

## Phase 0 原则

1. API 无状态，持久状态写入 PostgreSQL。
2. 容器生命周期以数据库记录为准，启动时可按标签校准实际 Docker 状态。
3. 外部输入在 API 边界验证；内部服务间使用明确的数据契约。
4. 敏感配置通过环境变量或密钥管理注入，绝不写入镜像、数据库或客户端。
