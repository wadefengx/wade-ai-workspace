# ADR-003 — MongoDB

## Status

Accepted

## Background

The product needs flexible document storage for workspace, chat, knowledge, memory, and evolving AI-related metadata.

## Decision

Use MongoDB with a replica set for local-first persistence and align repository data access around that model.

## Consequences

- Local setup must support replica-set behavior.
- Data modeling stays document-oriented and schema evolution remains important.
- API and service logic can optimize around flexible records and nested data.

## Alternatives

- Relational storage with stricter schema upfront.
- Embedded local databases with a later migration path.
