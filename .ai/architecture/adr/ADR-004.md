# ADR-004 — Prisma

## Status

Accepted

## Background

The repo needs a typed data access layer that fits the existing NestJS codebase and supports MongoDB consistently.

## Decision

Use Prisma as the repository data access layer and keep schema, seed, and generated client workflow close to the backend app.

## Consequences

- Schema changes remain explicit and reviewable.
- Validation and seed flows can stay standardized across phases.
- Prisma conventions influence backend module boundaries and test setup.

## Alternatives

- Hand-rolled MongoDB access for every module.
- A different ORM or ODM with weaker current repo alignment.
