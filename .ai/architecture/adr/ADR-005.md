# ADR-005 — Spec-Driven Development

## Status

Accepted

## Background

Parallel AI and human lanes need a clear source of truth to avoid drift, especially when touching shared contracts and acceptance logic.

## Decision

Use phase specs as the binding contract for scope, constraints, tasks, and acceptance, with workflows and AGENTS guiding execution around them.

## Consequences

- Specs must exist before parallel implementation starts.
- QA can validate against explicit wording instead of intent.
- Process docs, changelog, memory, and skills all derive from spec outcomes.

## Alternatives

- Ad-hoc task execution without a phase contract.
- Issue-only planning with no explicit acceptance narrative.
