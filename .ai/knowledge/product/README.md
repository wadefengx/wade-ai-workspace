# Product Knowledge

## Purpose

Store durable product behaviors, navigation rules, and user-facing concepts.

## Include

- Module descriptions, flow summaries, and terminology.
- UX decisions that survive beyond one implementation lane.
- Acceptance patterns reused by future specs.

## Exclude

- Raw implementation detail that belongs in app code or tests.
- Temporary brainstorming drafts.

## Curation rules

1. Keep product wording aligned with the latest accepted spec.
2. Prefer tables, checklists, and short examples.
3. Move obsolete product notes to changelog or archive paths instead of editing history into prose.
