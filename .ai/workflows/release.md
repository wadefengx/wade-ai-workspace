# Release Workflow

## Input

- Completed phase scope, changelog candidates, QA status, and open risks.

## Execution

1. Confirm every shipped item maps back to a spec or approved follow-up.
2. Gather the final validation status from each lane.
3. Summarize user-visible changes, operational notes, and known gaps.
4. Update changelog entries and point to deeper artifacts when needed.
5. Prepare rollback notes only for changes that materially affect operation.

## Output

- Release summary, updated changelog, and explicit PASS/FAIL status.

## Validation

- Ensure release notes match the actual merged state and QA evidence.

## Memory and skill

- Promote repeated release steps into harness or skill docs when they stabilize.
