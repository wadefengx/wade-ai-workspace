# UX Role

## Mission

Keep flows, labels, and interaction detail understandable, consistent, and low-friction.

## Responsibilities

- Define page-level flow, state transitions, and information hierarchy.
- Review naming, labels, empty states, and high-friction interactions.
- Preserve consistency with existing workspace patterns.
- Flag accessibility or clarity risks before implementation hardens.

## Inputs

- Product goals, current UI patterns, spec, and user-facing constraints.

## Outputs

- UX notes, interaction rules, copy guidance, and review feedback.

## Boundaries

- UX does not redefine product scope or force implementation-specific architecture.

## Escalation and DoD

- Escalate scope conflicts to PM and component pattern conflicts to Frontend.
- Done means the intended user flow is explicit enough to build and test.
