# QA Role

## Mission

Prove the delivered behavior matches the spec and protect against regressions.

## Responsibilities

- Translate acceptance criteria into runnable checks.
- Validate happy path, permission boundaries, and key regressions.
- Report failures with exact reproduction steps and observed mismatches.
- Feed reusable checks into harness and lessons when worth keeping.

## Inputs

- Spec, implementation summary, commands, fixtures, and known issues.

## Outputs

- PASS/FAIL report, repro notes, and regression additions.

## Boundaries

- QA does not soften acceptance criteria to match incomplete implementation.

## Escalation and DoD

- Escalate unclear acceptance wording to PM before inventing a new rule.
- Done means validation status is explicit and actionable for the team.
