# Scorecards Harness

## Purpose

Store concise rubrics for QA, release checks, and agent-output review.

## Include

- PASS/FAIL checklists tied to specs or workflows.
- Review rubrics for security, correctness, or UX acceptance.
- Lightweight scoring rules when comparisons are useful.

## Exclude

- Narrative release notes better stored in changelog.
- Rubrics with no owner or no target workflow.

## Usage rules

1. Keep categories observable and binary where possible.
2. Align wording with the active spec or workflow.
3. Reuse scorecards across phases only after at least one successful pass.
