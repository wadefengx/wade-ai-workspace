# Phase 14: Agent Expert System + Default AI Chat + Remove the `#` Prefix

## Goal

Three user requests:
1. **Default AI chat:** chat no longer requires `@AI` to trigger an AI reply — ordinary messages receive AI replies by default; mentioning a specific expert selects that expert.
2. **Agents as human experts:** Agents can be configured (CRUD already exists) and represent human-expert roles (such as PM/architect/frontend/backend/QA); every expert has an **emoji avatar + name**; the input can @mention each expert; clicking an expert opens a panel describing what the expert can do.
3. **Remove the `#` prefix:** remove the `#` before channel names in the sidebar (titles are already generated by AI, so the channel semantic marker is no longer needed).

Non-goal for this phase: harness runtime integration (Hermes/OpenClaw) only reserves **data-model and configuration UI**; actual invocation remains in Phase 15 and needs a separate ACP-bridge design.

## Current State (inspected)

- Frontend trigger: `workspace-shell.tsx:527`, `shouldTriggerAi = content.includes("@AI")` — the only entry point.
- Agent model (Prisma): `name` / `type` (five values) / `engineType` / `providerConfigRef` / `capabilitiesJson` / `isDefault`; it lacks emoji, role, and description.
- Agent CRUD APIs already exist: GET/POST/PATCH/DELETE (`workspaces/:wid/agents`, etc.).
- The sidebar hardcodes `# {channel.name}` in three places: `workspace-navigation.tsx:877/881/890`.
- The Agents page (`agents-page.tsx`, 548 lines) already has six presets and a form, but lacks emoji/role/description fields.
- Chat-input Suggestion already includes members + an `@AI` candidate (`workspace-shell.tsx:741-742`).

## Tasks

### Task 1: Default AI Chat (without `@AI`)

1. In `workspace-shell.tsx` sending logic, remove the conditional `shouldTriggerAi = content.includes("@AI")`; change behavior to:
   - A message containing `@expert name` goes to that expert (AgentEngine executes with that Agent).
   - A message containing `@AI` or no @mention uses the default Agent (existing `ensureDefaultAgent`).
   - A message that only @mentions members (not AI) is saved but does not trigger AI, preserving collaborative semantics.
2. Move trigger determination into the send flow: POST every message to the channel, then **always** call the AI stream unless it is member-only. Keep `@AI` in Suggestion but no longer require it.
3. Update input placeholder: “Send a message to chat with AI; @mention an expert to select one”.

### Task 2: Agent Specialization (emoji + role + description)

**Prisma schema:**
```prisma
model Agent {
  // Preserve existing fields
  emoji        String?   // Expert emoji avatar, e.g. 🧠
  role         String?   // Role title, e.g. "Senior Frontend Engineer"
  description  String?   // Panel display: what this expert can do
  systemPrompt String?   // Expert system prompt (optional; use default when empty)
}
```

**Backend:**
- Add optional `emoji` / `role` / `description` / `systemPrompt` fields to AgentService CRUD DTOs, maintaining compatibility with old data.
- In `streamAgentReply`, use the mentioned Agent’s `systemPrompt`; otherwise use the default.

**Frontend `agents-page.tsx`:**
- Add emoji (text or emoji selector), `role`, `description`, and `systemPrompt` to the form.
- Show emoji + name + role on list cards.
- Complete expert defaults for the six presets (for example: 🤖 default assistant / 🧠 architect / 🎨 designer / 🔧 frontend / ⚙️ backend / ✅ QA).

**Chat-input @expert mentions:**
- Suggestion candidates: members + **every Agent (emoji + name)**.
- Message rendering: highlight @expert mentions (reuse the purple `@All` highlighting mechanism; color may vary by Agent).

**Expert panel:**
- Clicking an @expert mention in a message or a sidebar/input candidate opens a Popover/Drawer showing emoji, name, role, and description (“What I can do”).
- Reuse Ant Design `Popover` for a lightweight implementation.

### Task 3: Remove the `#` Prefix

- In the three occurrences at `workspace-navigation.tsx:877/881/890`, change `# {channel.name}` to `{channel.name}`; remove `#` from matching `aria-label` values.

### Task 4: Harness Reservation (foundation for Phase 15)

- Add `harness String @default("OLLAMA")` to the Agent model (`OLLAMA | HERMES | OPENCLAW`); show the harness label alongside type selection on the Agents page.
- Data layer + UI display only; do not implement invocation (Phase 15 handles ACP bridging).

- [ ] Typing `@` in the input shows member + expert candidates; clicking @expert shows the “What I can do” panel.
